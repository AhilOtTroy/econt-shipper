# Dependencies for the watermark remover.
#
# Install order (the launcher does this for you):
#     pip install --no-deps iopaint==1.6.0
#     pip install --no-index --find-links wheels antlr4-python3-runtime==4.9.3
#     pip install --only-binary=<list> -r requirements-watermark.txt
#
# WHY --no-deps ON IOPAINT
# IOPaint 1.6.0 pins Pillow==9.5.0 and gradio==4.21.0. Neither has a Windows
# wheel past Python 3.12, and gradio 4.21.0 additionally caps numpy below 2.0,
# whose last release also stops at 3.12. Accept those pins and pip has to
# compile numpy and Pillow from source, which fails on a normal Windows box
# with no compiler. That is where "failed to build scipy" came from: scipy has
# wheels and is innocent — it was numpy 1.x being compiled inside scipy's
# isolated build step that died. Neither pin is real for us. LaMa runs fine on
# current Pillow, and gradio is only for IOPaint's own web UI, never started.
#
# WHY THE VENDORED antlr4 WHEEL
# omegaconf (which IOPaint imports) hard-pins antlr4-python3-runtime==4.9.*,
# and 4.9.3 is published as an sdist only — no wheel exists on PyPI. That is
# one guaranteed source build on the user's machine, and it is exactly the
# package that failed first on the dev box. It is pure Python, so wheels/ has
# a prebuilt py3-none-any wheel of it. Installing that first means nothing is
# ever compiled during setup.
#
# WHY PINNED
# These are the exact versions verified end to end. Leaving them open means
# every install rolls fresh dice on a stack this fragile.
#
# Verified on CPython 3.12.13 (the same standalone build the launcher
# downloads): installed with no source builds, downloaded both model weight
# sets from empty, and cleaned all three sample images through the CLI and
# through the web UI.
